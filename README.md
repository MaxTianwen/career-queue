# Career Queue v1.4.11

**中文** | [English](Readme_EN.md)

个人加拿大 co-op / intern 求职工作台。手动或本机定时发现岗位，筛选 Winter / Summer / Fall 2027 职位，保存到 Notion，并为选中的岗位准备、预览和修改一页简历。

**发现职位 → 已保存 Queue → 生成 / 审阅材料 → 确认材料并保存为待提交 → 本人确认已投递。**

当前版本：`v1.4.11`（2026-10-03 发布至 GitHub main / v1.4.11）。Qualcomm 明确的 May/June 2027 入职归入 Summer；Amazon 多季岗位保留一张卡，入职季和时长必须由同一官方选项满足。发现、Queue、详情与学校对照共用 JD 依据；不改已保存身份、申请记录、评分或自动排除规则。详见 [验收记录](docs/releases/v1.4.11-verification.md)。

## 启动与验证

需要 Node.js 22+；本机验证为 Node.js 24。核心程序无 npm 运行依赖；可选 OpenClaw 单独安装，在项目根目录运行：

```powershell
npm start
```

打开 http://127.0.0.1:4317 ，服务仅监听本机。使用此手动命令时需保持终端运行。已启用下方后台方式时直接打开网页，不必重复启动。

没有私人配置也可打开 Dashboard、体验明确标注的演示工作区或手动触发公开岗位搜索。正式 Queue 需要 Notion；匹配评分需要当前简历及本机 Python 文本读取环境；简历生成 / 编辑及 PDF 预览需要本机文档环境。公开源码不含这些私人资料，不是开箱即用的通用简历编辑器。

```powershell
npm test
node src/cli.mjs check
node src/cli.mjs preview --input examples/jobs.example.json
```

示例为合成数据，不要导入正式 Notion。本版新增资格、有效性、输入版本和历史材料保护测试，最终回归结果见 [CHANGELOG](CHANGELOG.md)。公开官网只读抽查与模拟 API / 演示测试分别记录；没有测试写入正式 Notion 或实际投递。没有私有文档环境的公开副本会跳过对应文档保护测试，不能将跳过等同通过。`check` 仅检查配置；`verify` 才读取真实 Notion schema。

## 后台自动发现

v1.3.2：当其他操作正在保存时，定时检查只记录“本次暂缓”，由原日程下一次再检查，不另开搜索、不增加重试次数。手动操作仍提示稍后重试；认证、输入冲突和真正失败不冒充成功。“后台检查详情”可展开查看最近日程核查、网页服务 / 调度后台记录及建议；超过 90 秒的记录明确标为过期，不自动结束未知进程。

Dashboard 新增每日发现状态、暂停 / 恢复、立即搜索和运行记录。固定 **America/Toronto 每天 09:00**，自动随夏令时调整，结果仅留在 Dashboard。

v1.3.1 起区分“后台正在启动”“连接待核实”和实际暂停；未确认连接时暂停 / 恢复按钮不可用，手动搜索仍可使用。状态栏保留上次完成搜索，并明确显示补跑、等待网络、自动重试耗尽和部分来源失败。后台核对 Dashboard 的工作区身份和 Gateway 的认证响应，遇到其他程序占用端口只报告，不结束其进程；已启动但尚未就绪的子进程不会重复启动。

- 关机 / 睡眠时不能运行；登录并启动后台后，当天补跑一次。跨多日只搜索当前最新岗位，不补历史日报。锁屏或关屏且未休眠时可继续运行。
- OpenClaw 每分钟检查，应用限制每天自动成功一轮；09:00 后手动成功也满足当天任务。断网每 5 分钟检查恢复，不消耗搜索次数。实际搜索失败间隔 15 分钟，最多自动尝试 3 次，再失败可手动重试。
- 部分来源失败明确标注，算作一轮完成；全部失败保留旧结果。暂停只阻止后续触发，不取消正在搜索的任务。新增数量与上次完成快照比较，首次运行显示首次基线。

全新 Windows 安装需要额外安装固定版本 OpenClaw，再创建默认暂停的日程：

```powershell
npm install --prefix private/openclaw-runtime --no-audit --no-fund openclaw@2026.9.6
node scripts/setup-automation.mjs --startup
```

OpenClaw 需要 Node 24.16+（24.x）或 26.1+，以固定包 engines 为准。安装后在 Dashboard 点“恢复自动运行”。本机已配置并启用。Windows 任务计划程序中的 `Career Queue Background` 使用当前用户权限隐藏启动后台，不需要保持浏览器或终端开启；登录时启动，后台退出后每 5 分钟检查恢复。它只维护后台，搜岗仍由原 OpenClaw 日程控制，每天成功一轮。未登录时不运行，不唤醒电脑、不修改电源设置。手动后台启动：`.\scripts\start-background.ps1`；旧版安装可运行 `.\scripts\start-background.ps1 -Install` 迁移本项目的旧登录启动项。如不再需要后台自启 / 恢复，在任务计划程序中禁用此任务；Dashboard 暂停只暂停搜索。

Dashboard 4317、后台单实例锁 4318、需令牌认证的 Gateway 18791 均仅监听本机。凭证与 OpenClaw 安装 / 状态在被忽略的 `private/`，运行记录与搜索快照在 `output/discovery/`。无外部通知、模型、自动入 Queue 或投递；已关闭 OpenClaw 模型心跳及自主学习。

`npm run discover` 通过同一服务立即搜索；`npm run automation:status` 查看运行状态。需要本机 Dashboard 服务在线，后台日志在 `output/automation/`。

## 当前功能

### v1.2.2 本地逐句对照与审阅

- 详情点击“准备简历修改对照”，查看原句、建议内容、当前 Word 中的支持原句与位置、相关 JD 原句。关键词对应只解释排序，不证明资格满足。
- 同一经历内的原文交换整组接受或保留，避免只接受一半造成要点丢失或重复；所有选择默认留空。没有安全调整时明确保留原文副本。
- 确认后另存 DOCX / PDF，沿用原格式、字体、字号和严格一页检查，最新 PDF 自动关联，最终材料审阅仍需本人确认。
- PDF 预览新增“查看修改依据”。手动编辑另存原句 / 新句并标注事实未自动核实；旧版本没有记录时如实说明。原稿与历史不覆盖。
- 对照绑定岗位、JD、简历文件和评估版本；20 分钟过期、服务重启或输入变化后重新准备。失败保留页面选择，不发布未通过检查的材料。
- 按用户确认，本版只做本地原文重排与审阅，不接入模型、不做语义改写、不从历史知识库补写内容。

### v1.2.1 多来源发现

- 搜索同次读取 Simplify / Pitt CSC 索引与 Tenstorrent University、Cohere、Telesat、Vena Solutions、Genesys、Celestica、Veeva Systems 的公开列表；这是七个指定雇主，并非 ATS 全量搜索。
- 来源失败仍保留其他结果；来源统计分开展示原始条目、范围内候选、独立新增 / 待核实、重复归组、实际全文读取与字段取得数量。
- 合并保留完整来源 JD 与链接，不拼接冲突要求；薪资保留币种 / 周期原文、任期范围和办公方式保留依据，不猜缺失值。
- 本次真实只读搜索新增 3 条待核实候选（其中 Cohere 两条 Winter 2027）；明确通过全部规则的新增为 0。抽查及覆盖边界见 [数据来源](docs/DATA_SOURCES.md)。


### v1.2.0 资格、有效性与材料依据

- 职位详情独立展示必需 / 加分 / 任选要求、JD 原句及当前简历证据。未写进简历不等于不会；复杂、否定、学历、学籍或工作资格保持待核实，只有本人确认与当前 JD 的必需条件冲突才硬排除。按用户要求，返校安排不作为筛选或确认事项。
- 本人核实只保存在当前岗位，绑定 JD 版本；JD 改变后不沿用旧确认。Match Score 继续使用当前启用简历，权重不变，不混入知识库或人工资格答案。
- 生成 / 准备前复查选中岗位的官方来源，显示开放、已关闭或暂无法确认及核查时间。开放核查在 15 分钟内可复用；明确关闭阻止新生成，超时、维护、跳转或缺失正文不会自动判关闭。无法确认时，可打开官网核实并填写依据后继续。
- 评估关联 JD、当前 CS / Data 基准版本与哈希、规则和核实记录。输入变化后重算，并提示旧材料需要重生成或明确重新审阅。生成、在线编辑、材料确认及投递记录保留对应快照，原稿与已投 PDF 不覆盖。
- 本版仍使用现有发现入口与本地规则，没有增加搜索源、模型或自动填表。真实只读抽查中 RBC Workday 返回开放，Super Ashby 保持无法确认，不能据此推定后者已关闭。

### v1.1.3 学校列表与双渠道记录

- 顶部“学校待办”按官网已投 / 学校待补、未关联、要求待确认、学校已交及已过学校截止等范围查看。学校状态保存在原 Notion 申请的 Payload，不新增申请库，也不要求改 Notion schema。
- 在已保存职位详情手动关联学校 ID / 链接，明确是否需要学校提交，分别保存学校和官网截止日期。打开链接不改变状态；本人确认学校实际提交时记录日期、确认时间、可选回执，以及实际材料快照或本人填写的材料说明。官网确认也保存独立快照；历史记录缺少确认时间时明确标注。
- 支持更新未提交的学校来源、解除误关联并重建，历史快照保留；学校已交快照不可直接覆盖。不自动登录、填表或提交，是否可补交以具体学校岗位要求为准。
- “学校待办 → 粘贴学校列表”支持网页制表符文字与 Markdown 表格：识别后可修改字段，再匹配已有申请，逐项勾选确认后保存。每批 1–100 条；区分强身份 / 疑似 / 未找到 / 已关联，支持重复导入和部分失败反馈。未匹配行不自动入 Queue，原始粘贴内容不保存为第二个职位库。
- 学校 ID 与雇主编号分开；标题中的 JR 编号或明确数字编号可提取，任期数字不当作编号。复制条数少于页面总数时提示；同一雇主编号对应多个学校 ID 时提示核对。
- 缺少链接不阻止匹配，可按学校 ID 查找并在详情补充链接。App Status 只供核对，不推定已提交。学校截止保留原文和分钟精度，无时区时按多伦多时间；重新粘贴缺失的可选字段不会清空已经补充的信息。

## 搜索和评分边界

- 自动发现使用 Simplify / Pitt CSC 的 Summer2027-Internships 与 3 个指定雇主公开列表，统一筛选和归组；不是全网搜索。
- 自动官方 JD 读取支持 **Greenhouse、Lever、Ashby、Workday**；手动链接 `fetch-job` 入口只支持 Greenhouse。接口、日期含义与覆盖限制见 [DATA_SOURCES](docs/DATA_SOURCES.md)。
- Workday 从受支持的官方职位页读取 JobPosting 正文 / 日期 / 编号，无需账号或付费 API；重定向、登录页、缺失或冲突数据保持失败提示。不是全 Workday 岗位搜索。
- 24 小时是可选视图，不是岗位有效期。首次发布、官方日期、最近重新发布分别标注；未知日期不使用索引收录时间代替。
- 已识别截止时间且已过期的岗位从发现列表和待选 Queue 隐藏，申请历史保留。未知 deadline 保持待核实，不能保证识别全部关闭岗位。
- Match Score 读取当前启用的 CS / Data 简历，标明文件名和版本，不使用历史知识库。尚未上传时读取原有固定简历基准；无法读取或扫描 PDF 无有效文字时不评分。混合 / 未知方向分别计算两份简历，排序采用较高的单份分数，不合并技能。分数是本地关键词证据覆盖：技能 70%、经历主题 30%，无识别项的部分重新归一化。详情提供依据及缺口；不等于 ATS 分数、完整资格判断或录取概率。
- v1.1.1：方向筛选复用职位名称与 JD 职责判断；正文分段显示，绿色为当前简历提及的技能、黄色为基础接触、蓝色为相关经历，悬停或聚焦可查看依据。纯文本来源按阅读需要排版，不承诺恢复官网原版式；原始 JD 不改写。
- 默认地域规则：GTA 现场 / 混合 4–16 个月，GTA 外至少 8 个月；远程不套用异地最短任期限制，但是否允许从加拿大办公仍须核实。
- 明确无薪排除，薪资未披露不等于无薪。最低工资不硬编码，无可靠比较依据时待核实。

## 简历操作与环境

v1.1.1：顶部 **我的简历** 可分别上传 CS / Data 的 Word（`.docx`）或 PDF，单文件最大 10MB。成功上传即成为该方向的当前基准，保存在 `private/resume-bases/`；下次打开或重启仍沿用，历史基准可预览、重新启用。原文件不覆盖。

- Word 原稿先通过一页和可读取文字检查；仅识别可安全编辑的正文。按 JD 重排同一经历内、格式一致的相邻要点，其他内容保持原样，不混入旧简历或旧知识库的事实，不进行模型改写；没有可重排内容时保留原文。
- PDF 可以保存、预览及用于评分，但成为当前基准后暂停该方向定制，需上传同版 Word；不会偷偷回退旧稿。复杂 Word 模板未识别安全正文时同样暂停。上传失败保持原基准。
- 定制记录保存所用基准名称 / 版本，在线编辑历史材料沿用该版本的正文范围，不受之后上传影响。上传或切换基准后，Match Score 与 JD 高亮重新计算。评分依据启用的基准简历，不使用某个岗位的定制稿代替基准。
- 工作台采用顶部导航、桌面侧边筛选和双列卡片；手机端单列，保留组合筛选、条件标签和一键清空。匹配依据、详细来源和全文在详情中查看。

1. 打开职位详情，查看资格与开放状态，选择自动 / CS / Data，点击“准备简历修改对照”，逐组选择应用或保留原文，确认后生成。核查无法确认时先由本人打开官网核实；已关闭或已确认必需条件冲突时停止生成。
2. 检查通过后自动预览 PDF；历史文件从“查看已生成版本”进入。
3. 预览中点击“编辑文字”，修改摘要、技能、项目 / 工作经历正文，再“保存新版本并预览”。
4. 标题、教育、联系方式和段落结构锁定。原稿及历史版本不覆盖，手动事实由本人核实。
5. 超页或格式失败不发布材料，不缩小字号 / 页边距；输入保留供调整。
6. 在“申请材料”预览自动关联的 PDF，确认事实和排版后勾选审阅并保存为待提交。旧版输入或缺少版本依据的材料需重生成或明确重新审阅。简历 PDF 必需，Cover Letter 通常可选、岗位要求时必需；DOCX / review.md 留在本机。也可切换“改用本机 PDF”。已确认记录保存材料版本与哈希，重新生成不覆盖已确认附件。

定制为本地规则，未接入大模型；仅选择已核对事实，不编造经历、技能或成果，不保证 ATS / AI 通过。`prepare --key '<key>'` 仅导出上下文，网页生成入口才执行定制。

原始简历只读。最初固定模板 / 基线 PDF / 事实映射及运行环境配置位于本机 `private/resume-templates/`，知识库为 `career_knowledge_base.md`。Windows Microsoft Word 隐藏独立实例只读导出，Python / pdfplumber 检查格式、字体、字号、边界、可提取文本和一页限制；预览也在本机渲染。Python 路径在私有模板配置。其他机器仍需配置 Word 与 Python 环境；新简历应从“我的简历”上传并检查，不直接替换私有配置中的模板文件。

## Notion 接入

Notion 是正式申请记录的唯一存储；Queue / Applications 为同库两个业务视图。本机已完成授权及 schema 验证，机器专属信息仅见 `private/SETUP_STATUS.md`。

新环境将 `.env.example` 复制为 `.env`，填写 token 并授权 integration 访问专用数据库；不要覆盖已有 `.env`。已有数据库填写 ID 后执行：

```powershell
node src/cli.mjs setup
node src/cli.mjs verify
```

`setup` 只补字段，类型冲突停止。已有数据库不要重复 `init`；仅其他全新工作区需创建时使用 `node src/cli.mjs init --parent '<页面UUID>'`。多 data source 时明确配置 `NOTION_DATA_SOURCE_ID`。

Queue 过滤 Status = Queue；Applications 过滤待提交 / 已投递 / 面试中 / 已结束，排除归档。正式字段为 Position（title）、Company、Location、Salary、URL、Notes、Status、Application date、Next step、Term、System notes、Materials、Key、Payload、Last seen。人工备注不覆盖，内部字段可隐藏。

## 发布与已知限制

- 代码、合成示例、当前文档为 GitHub 候选；凭证、知识库、模板、生成材料、日志、缓存、历史备份由 `.gitignore` 排除。机器专属 AGENTS.md 和未验证的 OpenClaw 草稿保留本机，不纳入公开 v1.0。
- `.gitignore` 不会移除已提交的敏感文件。提交 / 推送前检查暂存区和历史；即使是私密仓库，也不纳入凭证、私人简历或生成材料。尚未选择开源许可证。
- 单服务写操作串行；不要同时通过 CLI / 多个服务写同一记录。Notion 没有跨客户端事务与唯一键保证。
- 无自动投递、自动填表、批量简历、邮箱同步或模型 API。
- 本机功能验证不等于完整真实申请验收；尚未以真实材料上传并走完待提交 / 已投递链路。

后续规划见 [ROADMAP](ROADMAP.md)：v1.2.1 已按授权发布；v1.2.2 本地对照与审阅已发布，模型语义改写按用户选择暂缓；v1.3 已完成本机 OpenClaw 定时发现。半自动申请移入 v2.0，与面向 CS / Data 的多用户试用分阶段推进：先做好账号和资料隔离，再试点少量网站辅助填写，首轮建议由本人点击最终提交。具体网站、模型、费用与资料范围在实施前确认。v2.0 尚未开工；当前支持手动与每日定时搜岗。

### 学校列表中有、发现页没有的岗位

在“学校待办 → 粘贴学校列表”识别并匹配。未匹配行选择“新增到 Queue（待补 JD）”并勾选确认，即可在“已保存 / 待处理职位”看到。只有选中的行会保存；同一学校 ID 重复导入复用已有记录。

候选详情中填写对应官网链接，JD 留空可尝试受支持的官方读取器，或手动粘贴完整正文。本人核对后保存，之后才评分和准备材料。学校截止时间与官网截止时间分别保留；没有正文时不会按标题给分，也不会生成材料。若官网职位已经保存，先解除候选的学校关联，再关联已有申请并归档候选。

Vena 主动发现使用公开 Pinpoint 列表及对应详情页，只支持已核实的 lifeatvena.com 主机，不代表全量 Pinpoint 搜索。
