## 当前代码对部署的影响

| 实现 | 部署前要做的工作 |
|---|---|
| 仅本机监听、校验本机 Host / Origin | 明确域名和可信代理；HTTPS、Secure Cookie、跨站请求及会话撤销在实际入口复测，不能只解除本机限制。 |
| SQLite 内保存账号、原文件及版本 | 选择持久磁盘位置与备份权限，启动和迁移前校验；不能放在会被重建清空的临时目录。 |
| 本机 Word COM、Python 解析与渲染 | 当前依赖 Windows 桌面 Word；不能承诺迁入任意服务器仍保持一页和字体。远程生成需要独立方案及原件对照验收。 |
| 本机最多 20 账号、每人 500 职位和 20 个 / 20MB 文件 | 明确首批邀请规模；评估容量、任务串行等待与上传隔离，失败不发布半套文件。 |
| 全实例登录尝试限额 | 邀请环境须避免一个账号耗尽所有人的尝试额度，同时保留防滥用；实际代理下验证限流身份。 |
| 本机维护命令恢复密码 | 远程找回需要明确维护者核实身份的流程；不能把本机命令直接变成网页管理员接口。 |
| 独立目录恢复验证 | 备份不含环境配置、Word 临时目录；需在目标环境验证恢复、停服切换与回滚。 |

## 待选择的部署方案

部署位置、预算及资料允许保存的地区尚未确定。以下是范围选择，不是已批准方案：

1. **邀请首版使用已准备 PDF**：远程完成账号、简历匹配、材料预览和提交记录；严格 Word 生成继续留在本机。实现依赖较少，但远程用户暂不能直接生成 Word 定制稿，必须先获用户确认该范围调整。
2. **邀请首版包含严格 Word 生成**：先验证目标环境的文档执行隔离、字体、原稿保真、并发与失败恢复，再开放邀请。不能偷偷改用另一渲染器、缩小字号或放宽一页要求。

不默认让个人电脑直接暴露公网；不把现有管理员密码或个人数据复制给试用环境。服务商与价格在用户选定方向后查验，不在本文写入猜测报价。

## 已准备的实施与验收顺序

1. 确定托管环境、费用上限、资料位置和上述材料范围；准备独立配置与全新凭据。
2. 在隔离环境先部署空实例与合成账号，验证实际 HTTPS、注册控制、会话、跨账号文件访问、限流和上传限制。
3. 用完整旅程重复验证：不同简历与偏好、材料历史、双渠道、输入变化、改密、个人导出；Word 若纳入则必须是真实目标环境导出。
4. 备份到独立受控位置，验证损坏拒绝、恢复后旧会话失效、原件哈希和历史完整；演练明确切换和回滚，不覆盖唯一数据副本。
5. 收口邀请说明、已知限制、维护恢复与反馈入口，再请用户确认实际部署 / 邀请及 GitHub 发布。一次完整结果形成 v2.0.0，不按每个内部任务另发补丁。
