# v2 本机收口与 v1 迁入准备

2026-10-04。本阶段只准备迁入边界，没有读取 Notion 私人附件或导入正式记录；不等同于已完成迁移器。

## 当前可用范围

本机 4322 支持账号隔离、当前简历匹配、岗位保存、Word 生成及正文编辑、一页 PDF 校验、材料审阅、双渠道本人提交及带原因的更正、学校粘贴对照与关联维护、个人导出及独立备份恢复。原个人版 4317 与原每日 09:00 日程继续独立运行。

## 迁入前必须处理的映射

| 数据 | v2 接收方式与限制 |
|---|---|
| 账号归属 | 明确唯一目标账号；不默认向所有账号复制个人知识库、偏好或 Notion 授权。 |
| 岗位标识 | 保留 v1 原 ID 与 v2 UUID 的映射；用招聘编号、链接、批次核对，不只按标题合并。 |
| 简历原件 | 按目标账号保存不可变原件，核对后启用；旧个人模板不能默认为每人的模板。 |
| 材料与附件 | 需要实际文件、哈希及版本快照；临时下载链接不算文件已迁入。材料缺失须列为冲突，不伪造审阅记录。 |
| 实际提交 | 官网与学校分别映射日期、回执、所用材料；Queue、材料已生成或网页 Applied 字样不能自动变成本人提交。 |
| 学校记录 | 保留 School ID、学校独立截止和来源快照。当前一个职位只能关联一个学校 ID；多 ID 冲突须预览后处理。 |
| 关联与审计 | 保留原始来源与历史。学校关联变化不能移动官网提交或当时材料；已有对应学校提交禁止直接解除、改绑。 |
| 搜索与调度 | v2 有手动公开来源刷新；v1 每日调度尚未迁入，不能宣称 4322 已接管每日任务。 |
| 开放状态 | v1 官网开放复查未完整迁入 v2；截止及本人确认不等于自动验证官网开放。 |

## 后续实施顺序

2026-10-05 只读代码核查：旧版 `/api/jobs` 会过滤已归档及部分已截止 Queue，不能把 Dashboard 当前列表当作完整迁入来源；`/api/portal` 也只返回学校摘要，缺少完整材料和历史。后续应从原存储层只读取得完整记录，预览中分别计数已归档、已截止及缺失证据，不能直接调用列表接口后声称“全部已读取”。

需要核对的原字段包括 `key`、`portal`、`portalHistory`、`materialVersion`、`externalSubmission`、`applicationDate`。旧版以状态和日期推导的“已投递”应在预览中标明证据来源，不直接升级为 v2 的新本人确认。只读预览本身不写入 v2 的提交、审阅或学校审计表。

用户已确认唯一目标为本机目标账号，预览已保存职位、学校关联、材料清单及双渠道历史。2026-10-05 已完成只读清点：已选职位、既有生成版本，无学校关联或提交记录；详见 releases/v2-migration-preview-verification.md。未执行导入。

1. 用户确定迁入范围及目标账号后，只读生成清单和映射预览。
2. 对缺失文件、重复编号、多学校 ID、提交日期或材料不完整的记录列出冲突，不自动猜测。
3. 用隔离副本试迁，核对文件哈希、各渠道历史、重试去重及恢复能力。
4. 展示具体迁移结果和冲突处理方案，再确认正式导入；保留原 v1 数据和独立备份。

远程部署、模型语义改写、跨站半自动申请和学校登录抓取不属于本机收口。当前发现范围仍为部分加拿大 CS / Data co-op、intern 来源。
