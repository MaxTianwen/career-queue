# 有限范围本机迁入

只支持单条无学校关联、无已审阅材料、无提交历史的 v1 Queue 职位及历史生成文件。其他状态必须停止并另行设计，不能删掉原字段来绕过检查。

## 流程

1. 只读取得完整来源与原文件，准备私人 JSON 包；目标账号必须已经存在，不创建账号或修改密码。
2. 执行只读预览，核对目标账号、公司、职位、文件名、版本、基准标识和哈希。
3. 在正式账号副本中试迁，验证回滚、重复执行、导出、备份恢复及不改变材料/提交状态。
4. 向用户展示具体清单，获得正式导入确认；执行前备份，并重查预览仍一致。
5. 显式指定数据库、迁入包、账号和预览 fingerprint 执行。成功后检查来源记录及文件数量；保留备份，不自动删除旧版资料。

命令（占位路径，不能直接照抄为正式导入）：

```powershell
node scripts/v2-migrate.mjs preview '<数据库>' '<私人迁入包.json>' '<账号>'
node scripts/v2-migrate.mjs apply '<数据库>' '<私人迁入包.json>' '<账号>' '<刚刚核对的 fingerprint>'
```

`preview` 使用 SQLite 只读连接，不创建目录、表或记录。`apply` 是本机维护入口，没有浏览器写接口；不连接 Notion，不执行日程切换。确认标识包含目标账号、来源与文件内容、目标职位及文件清单；目标变化后旧标识失效。它核对的是准备好的来源快照，不会替代操作前对 Notion 最新状态的检查。

职位、文件与来源记录在一个事务内写入。相同来源与确认标识的已完成请求可重试，来源或映射变化拒绝覆盖。匹配到相同链接或公司标题时停止，不自动归并；容量不足、文件哈希不符和不支持的历史也停止。

历史文件保持未审阅状态；不启用为当前简历，不创建生成链、学校关联或提交记录。资料包会包含私人 JD、备注及简历原文，必须保存在 `private/`，不得上传 GitHub。当前来源快照保存职位主要字段，不保证完整迁移所有 v1 扩展字段，因此原 v1 数据与私人原始快照继续保留。
