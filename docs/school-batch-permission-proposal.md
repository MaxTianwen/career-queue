# 学校跨标签批量读取：待批准的最小权限方案

当前状态：0.1.9已在真实Brave完成一岗的明确可见字段读取、身份核验和本机回填。无可见返回控件；未验证隐藏/折叠内容或批量。当前manifest未增加任何权限。

## 拟批准的权限（尚未实施）

```json
{
  "optional_host_permissions": [
    "https://recruitstudents.torontomu.ca/*"
  ]
}
```

保留已有activeTab、scripting和本机工作台地址。不新增tabs、cookies、debugger、webRequest或其他网站权限。新增的是可选学校站点权限；在本人点击「授权本次学校批量」时才调用permissions.request，拒绝则不开始批量。

浏览器将此授权视为整个HTTPS主机的访问/脚本执行能力，路径不能作为浏览器权限隔离边界，不能声称权限只覆盖一个页面。程序仍严格限定已观察到的`/myAccount/coop/postings.htm`列表/详情、用户选定岗位、当前可见字段、必要的标题点击和自己创建的标签管理。不会读取密码、cookies、token、隐藏表单、账户页面或其他浏览记录，不调用隐藏接口，不申请岗位。

## 期限与撤销

目标是一次批次；完成、取消或失败时主动permissions.remove，并核实已移除。浏览器optional host授权本身没有自动的单批次过期保证：若扩展在清理前崩溃，权限可能暂留；下次后台启动先撤销遗留授权，界面提供立即撤销按钮。本人也可随时在Brave扩展详情的站点访问设置撤销，或禁用扩展。不得把主动撤销方案宣传成浏览器原生的临时授权。

## 批量标签方案（批准后实施并实测）

1. 保留原列表标签。记录本批列表、精确岗位身份和点击前已有标签ID，仅处理已确认的唯一标题动作。
2. 每次只打开一个岗位；通过创建事件、opener和新标签集合确认归属，再严格检查学校来源及标题/雇主/任期/可用ID。不能唯一确认就停止，不能自动采用单岗的人工重新绑定路径。
3. 核验后读取可见字段，保存逐岗检查点及失败原因；不推断隐藏内容完整。
4. 仅关闭本批明确创建且身份已核实的详情标签，然后激活保留的原列表并重新扫描。绝不关闭用户原有标签，不猜返回控件，不使用history.back。
5. 先进行两个岗位的小批实机验收，再运行用户选择的其余岗位。重复项跳过，失败/权限撤销/身份变化立即暂停。

学校host权限解决跨标签读取授权，但不保证页面脚本打开弹窗一定获准。默认弹窗拦截已在独立Edge合成页面复现，不能据此断言真实Brave原因。若授权后标题动作仍被阻止，应停止并报告；不能暗改弹窗设置、绕过浏览器拦截或猜测隐藏目标URL。若还需该站点单独的弹窗许可，必须另行说明和征求批准。

## 不扩权的替代方案与当前可继续工作

保留已验证的逐岗手动标题点击、在详情页调用助手读取；这不是无人逐岗操作的批量完成。权限决定前，可以继续离线测试身份绑定、去重、导入幂等、故障恢复、标签归属和权限撤销逻辑，以及维护现有本机数据。真实跨标签批量集成与GitHub最终推送继续等待授权和验收，不再重复要求相同单岗诊断。
