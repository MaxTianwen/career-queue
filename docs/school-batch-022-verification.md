# 0.2.2：独立、置顶的只读批次诊断

收到的 62 字节文件是 `career-queue-school-capture-v1` 且 `jobs: []`。它只能说明该文件包含零条岗位，不能证明真实批次是否启动、失败或完成，也没有权限清理证据。未据此判断用户点错按钮。

## 发现与修复

0.2.1 诊断按钮位于操作区下方，长清单或 600px 弹窗可能需要滚动。诊断和岗位数据共用一个“再次下载当前文件”链接。岗位按钮仅在异步状态返回后才被禁用，导出处理器和后台也未拦截空 `jobs`。没有发现诊断按钮调用单岗处理器的证据，但这些自身缺陷足以造成入口和下载文件混淆。

0.2.2 把“下载批次诊断 JSON”置于弹窗顶部，岗位操作默认折叠；同时自动显示可选中复制的 `CQ-BATCH/0.2.2 ...` 短状态码。诊断文件固定为 `career-queue-school-batch-diagnostic.json`、schema 固定为 `career-queue-school-batch-diagnostic-v1`。

诊断、岗位数据分别使用独立链接和对象 URL。岗位导出从 HTML 初始状态即禁用；前端处理器及后台均拒绝空结果，不生成空文件。状态变为空时清理旧岗位下载链接，不影响诊断链接。没有批次记录或没有成功岗位时仍可下载诊断；后台不可用时显示可复制的 `state=unavailable`，不会伪造成功诊断。

不新增权限、不申请授权、不点击职位、不导入岗位、不清空检查点。保留 0.2.1 已验证的安全恢复和权限清理逻辑；重新加载时已有恢复/清理机制仍会按原规则处理本批残留权限。

## 用户当前只需做的操作

重新加载现有扩展到 **0.2.2**，打开弹窗。最上方深色按钮就是 **“下载批次诊断 JSON”**，在 405×600 合成弹窗中无需滚动即可看到。也可以直接选中其下的 `CQ-BATCH/0.2.2 ...` 状态码并复制回复，不必再上传文件。不要展开“岗位读取与导入”，不要重新准备或授权运行。

## 验证边界

新增 UI 回归覆盖空记录诊断、处理器层拒绝空文件、链接/文件名互不覆盖、旧空链接清理、后台不可用提示和初始禁用。实际后台消息测试确认拒绝空岗位导出但允许诊断。连同已有权限/恢复测试，共 46 项定向检查通过。

用户电脑独立 Edge 以合成数据及 Chrome API 替身验证诊断按钮、状态码在窄弹窗中可见。完整回归与候选哈希证据见 `private/<local-evidence>`。真实 Brave 当前批次状态和真实权限撤销结果尚未验证；main 不提交、不推送。
