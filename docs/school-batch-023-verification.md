# 0.2.3：详情页面观察与安全恢复

## 已证实与未证实

已用旧控制器复现：同步创建且保留正确 opener 的新标签可识别；缺 opener 的新标签、复用既有标签、同页详情和没有页面变化，原来都被报告为 `NO_DETAIL_TAB_OBSERVED`。这是检测范围和诊断分类的缺陷。不能由此确定用户那次实际失败属于哪一种。

用户提供的 Shields OCR 是 Google tag 跟踪器被阻止，不是弹窗拦截证据。未关闭 Shields、修改浏览器策略、启用远程调试或新增权限。

## 当前处理

- 在任何批次消息可派发点击之前安装标签创建、更新、激活、关闭监听；只保留有界的标签 ID、关联 ID 和事件顺序，不保存其他站点 URL 或标题。持续存在的新标签仍由轮询补充，因此不把同步事件必然丢失当作根因。
- 标题点击回执增加“是否观察到 click 事件、isTrusted、当时 userActivation、defaultPrevented”布尔证据。`dispatched` 仍只表示调用派发，不能证明详情已打开；未把合成事件或没有变化直接判为弹窗拦截。
- 只在 `https://recruitstudents.torontomu.ca/myAccount/coop/postings.htm` 内核对可见标题、公司、学期及可见 ID。正文读取前再次验证。其他页面不注入读取，身份冲突或多个匹配候选停止。
- 缺 opener 的新详情和有更新/激活证据的复用详情可以读取，但均保留，不自动关闭。只关闭本批新建、关联明确且重新核对身份成功的详情标签。
- 同页详情验证成功后保存一岗并暂停，要求手动返回列表；不关闭原页，不猜按钮或调用 history.back。
- 恢复旧的已派发尝试时只核对现有页面，不再次点击。无本次变化证据的既有详情必须有独立可见 School ID 才能匹配，不凭相似标题猜配。已完成项不重新读取。
- 诊断区分未观察到页面变化、候选未就绪、身份不符、多个候选、相关新标签提前关闭及同页已捕获待手动返回，并记录观察模式。
- `revoked-recorded` 指存在本批撤销记录，不是当前全部站点权限已移除的证明；原有用户授权继续保留。

## 本次最少实机步骤

重新加载现有扩展到 **0.2.3**，保留原学校列表和任何已有详情标签。对现有失败批次选择“准备继续授权”，再选择“授权并运行两岗”，由本人确认 Brave 提示（若出现）。保留原清单与检查点；对于已经派发的第一岗，此次先核对现有页面，不重放标题点击。

若没有可安全匹配的详情页，会明确停止，不猜配或自动重试。此时复制顶部短状态码即可；不要关闭 Shields，不要求再提供同一截图。若是同页详情，保存当前岗后需本人返回列表再继续。
