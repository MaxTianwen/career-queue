2026-10-03：用户已采用“本机隔离验收，再部署邀请试用”及“应用自带存储，Notion 后续可选”。目前已交付账号与简历建议、PDF 材料 / 申请记录、隔离 Word 生成及本机备份 / 恢复验证 / 个人导出，不是完整 v2.0.0 发布，package 保持已发布的 1.5.0。

## 使用

在项目根目录运行 `npm run start:v2`，打开 http://127.0.0.1:4322/ 。首次使用点击“创建本机账号”。只允许本机回环连接；不支持局域网、公网、隧道或反向代理部署。

使用本机已验证的 Node 24.16 或兼容的更新版本。v2 使用内置 `node:sqlite`，没有新增 npm 依赖；个人版 `npm start` 和 4317 入口保持原样。v2 不读取 `.env`、Notion、原个人简历或知识库，只调用已接入的公开招聘来源，不调用模型或调度器；仅本人明确生成时使用本机 Word。

账号、偏好、手动保存职位及文件原件存入 `private/v2-local/workspaces.sqlite`。运行期间 SQLite 可能产生同目录 WAL / SHM 文件；目录已由 private/ 规则排除 Git。不要运行时只复制主数据库文件来声称完成备份；现在可使用下方维护命令创建一致性备份及独立恢复副本；现有个人资料迁移仍未实施。

界面可操作：

- 创建本机账号、登录、退出；退出及另一页面更换账号后清空私人内容。
- 保存各自的方向、地区和职位类型偏好；初始为空，不继承个人版 GTA / 2027 限制。方向、地区关键词（逗号分隔，任一匹配）、Intern / Co-op 类型现在实际用于建议筛选；旧版自由填写的其他类型会明确提示本期不支持，不静默替换。
- 手动保存 / 编辑职位和备注，选择卡片查看；保存失败保留输入；切换前确认未保存改动。
- 保存 PDF / DOCX 原件、查看文件列表并下载；同名再次上传为独立原件，不覆盖。单文件 5MB，每人最多 20 个 / 合计 20MB。文件只检查扩展名、大小及基本文件头，不代表文档结构、排版或安全扫描通过。只以附件下载，不作为 HTML 内联展示或执行。上传本身不代表启用。现在可以解析、查看文字并确认启用为评分基准；提取文字预览不代表原版式预览。

## 会话与存储边界

### 本机管理员（2026-10-03 补充）

用户要求直接创建个人使用的管理员账号。本机已创建 `admin`，无需注册；随机密码保存在忽略的 `private/v2-local/admin-login.txt`，代码与终端不包含密码。登录后显示“管理员”，可展开“管理员 · 注册设置”开放或关闭注册；关闭后已有账号仍能登录。管理员不绕过职位、偏好和文件的用户隔离。

本机维护入口 `npm run admin:v2` 仅首次创建 admin，重复运行不会覆盖登录信息、重设密码或将已有同名普通账号提升。脚本没有公开 HTTP 调用入口；网页注册始终创建 member，传入 role 字段不授予权限。角色升级为数据库增量列，不清空旧账号或记录。没有用户删除或代管私人文件；本人修改密码和本机维护恢复已接通，见下节。

- 账号为 3–40 位英文 / 数字 / 点 / 横线 / 下划线，忽略大小写；密码 12–128 个字符，使用随机盐与 scrypt（N=65536、r=8、p=2）派生保存，账号数据库不存明文；管理员初始化密码仅保留在上述本机私有交接文件。
- 随机会话令牌只在 HttpOnly / SameSite=Strict Cookie 中返回，数据库保存 SHA-256；8 小时到期。新登录撤销该账号旧会话，退出即时撤销。Cookie 未设置 Secure 是本机 HTTP 预览的限制，不适用于公网。
- 受保护记录 / 文件请求由服务端会话获取 owner ID，所有查询和修改带 owner 条件；不接受客户端指定所属人。异账号 / 不存在的 ID 均返回 404。
- 校验 Host / Origin / Fetch-Site；写请求必须有同源 Origin。受保护读写（除初始会话探测）还需当前会话的 CSRF 标识，避免共享 Cookie 更换后旧页面读取新账号数据。请求体读取完成后再次确认会话。
- 私人响应 `no-store`，静态资源固定白名单，用户文字以 textContent / value 显示；没有任意文件路径路由。退出通过 BroadcastChannel 清空其他页面；页面恢复时复查身份，迟到响应被丢弃。
- 本机账号最多 20 个，每人最多 500 条职位；15 分钟内全实例最多 20 次账号尝试，最多 2 次并发密码计算。限流记录持久保存。限流为本机预览设计，不代表公网防护验收完成。
- 数据库未做应用层加密；同一 Windows 用户或有文件系统权限的管理员仍能读取磁盘上的职位和原件。账号隔离指应用访问边界。

参考实现 API：[Node crypto](https://nodejs.org/docs/latest-v24.x/api/crypto.html)、[Node SQLite](https://nodejs.org/api/sqlite.html)。运行兼容性以本机 24.16 验证为准，未宣称各版本均已通过。

## 材料审阅与实际申请记录（2026-10-03）

在“已保存职位”选中岗位，下方“申请材料与记录”完成：

1. 明确选择申请渠道（待确认 / 仅官网 / 官网＋学校 / 仅学校）。没有外链不推断为仅学校；变更渠道不删除已有记录。
2. 先保存完整 JD，并启用自己的简历作为依据。材料 PDF 可以直接复用“我的文件”中已有原件，也可以在材料区上传新原件。上传不会自动启用为评分简历。
3. 预览所选简历 PDF 和可选 Cover Letter，逐页核对后勾选审阅并保存。原件不改，服务器核验简历一页；Cover Letter 最多 10 页。当前会话预览有效 15 分钟，重新登录或过期后须再次预览。
4. 材料版本保存实际 PDF 引用 / 哈希、当时岗位与 JD、启用基准的文件 / 文字哈希。相同材料和依据的重复保存复用版本，每岗位最多 50 版；不覆盖其他版本或原件。修改备注不使材料失效，JD / 岗位身份 / 启用简历变化会标记旧依据。
5. 本人实际在申请网站提交成功后，选择真实渠道、实际使用版本和多伦多日期，确认成功及所需附件齐全，再记录。成绩单等其他文件由本人在网站处理；系统不假定附件已齐，也不自动填写或提交。可以记录旧版本的历史提交，但依据已变化时须明确确认。
6. “申请记录”集中显示材料已审阅、部分渠道已提交、所需渠道已记录完成等状态。官网与学校分别冻结版本、日期和回执；新材料不替换旧提交。提交记录本期只读，不能修改、撤销或覆盖；输入前请核对，后续可增加带审计的纠正记录。

页面上的文件内容按用户授权读取。PDF 预览由现有 Python 的 pypdfium2 在隐藏子进程中生成 PNG，浏览器只显示图像；不向模型或外部预览服务传文件。读取限单文件 5MB、最多 10 页、单边页面大小和图像尺寸上限、20 秒进程超时；原件仍可下载。图像预览不可代替可复制文字的原件，不能声称由此通过 ATS。

上述为手动 PDF 阶段；后续 Word 隔离生成已接通，操作与边界见下节。材料记录验收见 [材料与申请记录](releases/v2-materials-verification.md)。


## 当前账号 Word 生成（2026-10-03）

在“我的文件”上传并核对启用 DOCX，再选中已保存职位 → “从当前 Word 简历生成” → “准备修改对照”。逐组选择保留或采用，核实岗位仍开放后生成；这次确认只用于当前请求，不保存为通用开放状态。明确可识别的 JD 截止已过会阻止生成；没有截止或读取不到关闭状态不代表仍开放，v2 尚未移植官网自动开放复查。

仅在同一经历内重排格式一致的相邻原文要点，不跨经历移动、不增加技能、不做模型语义改写；复杂模板或没有可重排要点时保留原文。PDF 基准不能自动定制，需上传同版 Word 并确认启用；不使用 v1 私人模板。

生成会先校验包结构（修订、动态域、嵌入对象、外部模板等不支持），再以只读 Word 导出原稿和调整稿，两者都必须是一页。原格式及非修改内容 XML、页尺寸、字体 / 字号、文字完整性、边界和原件哈希检查通过才保存。不会通过缩小字体凑成一页；不是 ATS 通过保证。

通过后的 DOCX / PDF 在同一事务内保存到本人文件库，PDF 自动选入材料区，刷新后可继续选用；仍须预览并本人审阅才成为材料版本，不自动标记已投递或切换评分基准。历史生成稿保留来源 JD、简历及对照选择；输入变化后标记旧稿，不能用于新的材料审阅，旧提交记录不变。

本机要求已安装 Microsoft Word，以及现有 Python 的 lxml、pdfplumber、pypdfium2 / Pillow；测试夹具另需 python-docx。已有 Word 进程时拒绝生成，不关闭用户文档。每个账号有独立随机工作目录，v2 文档任务串行并有 Windows 互斥锁；子进程隐藏，导出 90 秒上限。工作目录保留，便于核查失败，不自动删除；每账号最多 50 次准备 / 生成任务，达到后提示本人整理。若 Office 本身卡死或被系统阻塞，超时只保证不发布，不能保证 Office 子进程已退出；没有批量结束 Word 的行为，需关闭阻塞的 Word 后重试。既有每人 20 个 / 20MB 文件额度同时适用于生成稿，一次生成占两个文件；额度不足整次回滚。

本机隔离不是公网文档沙箱。生成稿在线文字编辑见下节；云端渲染与邀请部署按用户选择暂缓。本机备份恢复与本人数据导出已接通。验收见 [Word 生成验收](releases/v2-word-verification.md)。

## 生成稿在线文字编辑（2026-10-04）

已保存职位 → 从当前 Word 简历生成 → 展开一份生成稿 → **修改文字并另存**。编辑列出的正文段落，核对内容真实并确认岗位仍开放，点击“检查一页版式并另存”。导出失败或超页时保留输入供修改重试；不会缩小字体。成功后新的 PDF 自动选入材料区，仍需重新预览与本人审阅，不必下载后重传。

只开放可保持原格式的正文段落，不是完整 Word 排版编辑器；姓名、标题、表格和混合格式内容保持不变。每段 1–2000 字，不支持插入换行。只含 PDF 的材料不能在这里改字，需启用同版 Word 后生成。生成 / 编辑都使用本机 Word 并复用原格式、一页和文件完整性检查；请先保存并关闭已打开的 Word 文档。

每次成功另存新的 Word / PDF，保留来源生成稿与修改前后原句。原件、当前启用简历、评分及已审阅 / 已提交材料不改；编辑稿不会自动成为评分基准。JD 或基准变化后旧稿停止编辑，正在填写的文字保留供复制，须重新生成。编辑同样计入文件与 Word 工作目录额度，空间不足不会只保存一半。验证见 [在线编辑验收](releases/v2-editing-verification.md)。


## 本机备份、恢复验证与个人导出（2026-10-03）

页面“数据与容量”显示本人文件数量 / 大小、已保存岗位和 Word 工作目录占用。“下载我的资料包”包含已保存的原文件及 records.json（岗位、偏好、当前基准、解析文字、渠道、材料 / 生成历史和提交结果），不包含密码、会话、其他账号或未保存输入。文件在 ZIP 内用唯一 ID 命名，原名保存在记录中；本期不支持个人包导入。导出需要既有 runtime.json 中的 Python，仅使用标准库；输入超过 64MB 或历史过大时停止并建议完整备份。

在项目根目录手动创建完整 v2 备份：

```powershell
npm run backup:v2
```

成功后打印 private/v2-backups 下新目录，包含 workspaces.sqlite 和 manifest.json；数据库运行时也可创建一致性副本。校验数据库、外键、每个原文件哈希后才标记完成。包含所有账号的密码哈希和私人资料，未加密，不能上传 GitHub；浏览器管理员也不能下载完整备份。不包含 v1 / Notion、runtime.json 环境配置或 Word 临时工作目录，但所有已保存生成稿在数据库内保留。备份不自动定时或删除历史。

用上一步实际返回的备份目录验证恢复（替换示例路径）：

```powershell
npm run restore:v2 -- "D:\完整路径\private\v2-backups\备份目录名"
```

恢复只写入 private/v2-restores 下的新目录，校验成功后生成 restore-verified.json；不会合并、覆盖或自动切换当前 4322 数据。旧会话和临时 PDF 预览确认失效，登录后须重新预览；已审阅材料、实际提交记录和文件版本保持。损坏清单 / 文件、现有目标目录均拒绝；失败留下的目录保留，不批量清理。

这一步提供可验证副本，不是运行中一键灾难切换。真正替换当前工作区时先停止服务、保留原目录与 WAL / SHM、确认恢复副本和对应程序版本，再由本机维护者明确切换；本期没有网页恢复按钮，不提供自动覆盖步骤。恢复环境需另行配置 Python / Word，并重新验证文档生成。

见 [本阶段验收](releases/v2-data-verification.md)。密码管理及完整本机流程已验收，见 [本机收口](releases/v2-local-acceptance.md)；[部署准备](v2-trial-plan.md) 已完成，当前仍仅供本机预览。


## 修改密码与本机恢复（2026-10-03）

右上方“账号设置”验证当前密码并填写两次新密码，12–128 个字符且与当前密码不同。先保存其他页面的修改，再勾选退出确认。成功后该账号旧会话全部失效，重新登录；旧临时 PDF 预览须重做，原文件、材料审阅 / 实际提交记录、偏好和权限不变。输错旧密码或新密码不一致不改变账号，输入密码在请求结束后清空，重新填写即可。

忘记密码时，在本机项目根目录由有文件访问权限的维护者执行（替换为明确的账号）：

```powershell
npm run recover:v2 -- admin --confirm-reset
```

只重置指定的已有账号；缺确认参数、不存在账号都不会创建或提升账号。随机新密码写入 private/v2-local/recovery 下唯一文件，终端只显示文件路径；不要把密码作为命令参数或发到聊天。交接文件需妥善保管，本期不自动清理。该命令没有网页调用入口，普通用户或网页管理员不能代改其他用户密码。

成功后旧密码和该账号所有会话失效。初始 admin-login.txt 保留但不再代表当前密码；使用恢复输出文件中的密码登录，再自行修改。原角色和其他账号不改，不清除全实例的登录尝试限制；若触发限流，仍等待 15 分钟。已打开网页在下次请求或返回页面核验时发现本机重置并清理，并非推送式即时退出。

本轮仅在隔离账号验证此命令，没有修改现有 admin 密码。本人改密和恢复详见 [账号管理验收](releases/v2-account-verification.md)。本机恢复不替代远程身份验证；公网邀请部署仍未开放。

## 已提交记录填错时（2026-10-04）

在“材料与提交历史”展开所用版本，点击“更正这条提交记录”。可修改实际提交日期、官网 / 学校渠道、回执，并填写必需的更正原因。所用材料不能在这里替换。

原始值与每次更正的前后内容、时间、账号都可展开查看；申请记录按更正后的有效渠道显示进度。目标渠道已有另一条记录时不会覆盖或合并；旧页面保存冲突时保留输入，取消后核对最新历史再重新填写。本期不支持撤销误记，也不会修改申请网站上的内容。

个人 ZIP 导出和整库备份保留审计记录。升级已有本机数据库前先备份，并停止旧服务后再启动新代码；不允许旧进程继续使用新表结构。实际兼容 / 恢复 / 失败重试 / 页面验收见 [记录更正验收](releases/v2-submission-corrections-verification.md)。


## 学校列表对照（2026-10-04）

登录 4322 → 学校对照，将学校网页表格连同表头复制粘贴，每批最多 100 条。点击“预览并对照”，核对公司、招聘编号、学校 ID、批次和地点；逐行选择关联已有职位、保存公开候选并关联，或保存独立学校候选，最后勾选确认并保存。筛选会保留隐藏行的选择，保存前查看选择数量。

未找到不等于岗位关闭；没有完整 JD 的候选先保留，打开已保存职位补正文后才能评分和准备材料。复制的 Applied / Apply 不算本人提交，学校截止独立于官网信息。可筛出“官网已交 · 学校待补交”，打开职位沿用材料预览及本人提交记录流程。

失败保留原文和选择，可重试；预览过期需重新对照。已有关联不自动覆盖；来源变化可点击“核对并更新学校资料”，或在已保存卡片点击“维护学校关联”。更新、解除和改绑均需预览差异、填写原因并确认。仅对应 School ID 的学校实际提交会锁定解除 / 改绑，官网提交不锁定。改绑仅更换学校关联，不移动原职位、材料、渠道或提交。已提交学校来源仍可更新，旧快照及完整操作历史保留。冲突时取消并重开核对，刷新不覆盖草稿。已解除记录可在操作历史中查看。详见 [维护验收](releases/v2-school-maintenance-verification.md)。一个职位当前只关联一个学校 ID。学校关联随个人导出及完整备份保存，其他账号不可见。详见 [本阶段验收](releases/v2-school-verification.md)。

学校提交区显示当前 School ID。若打开页面后关联变化，旧页面保存会被拒绝；刷新材料区会取消旧的提交确认，保留日期和回执供重新核对。首次将官网记录更正为学校渠道时同样检查关联版本；已经保存的学校来源身份不会随当前关联改写。
