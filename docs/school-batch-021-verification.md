# 0.2.1：学校小批授权与后台恢复修复

## 已确认的代码缺陷

0.2.0 的恢复逻辑将 `prepared`、`armed`、`requesting`、`running` 统一设为 `WORKER_RESTARTED_REAUTHORIZE`。准备完成后的正常后台回收会造成不必要中断；如果用户的原生权限提示仍活跃，新后台还可能撤销刚授予的权限。旧回归覆盖了“应当停止”的场景，未覆盖“原授权提示仍活跃”的必要场景。

用户截图显示 0.2.0 的两岗清单及该恢复码，证明已进入批次恢复分支，不能证明岗位是否执行、成功或失败。此前上传的旧单岗 JSON 也不能证明批次结果。未读取真实 Brave 的 IndexedDB，未重跑真实岗位。

## 修复

- 准备/待授权状态在后台重建后保留，不自动判中断、不自动点击。
- 每次授权使用独立请求标识，并绑定浏览器提供的弹窗 `documentId`。原弹窗仍活跃时保留请求和新授权；不同弹窗不能冒充旧请求。使用现有 runtime API，不新增权限。官方 API 依据：[runtime getContexts / ContextFilter / MessageSender](https://developer.chrome.com/docs/extensions/reference/api/runtime)。
- 原生授权调用仍同步发生在本人点击中。授权开始回执丢失时仅重试同一幂等后台消息，不再弹一次原生授权。
- 重复接受/拒绝回执幂等，不取消正在运行的批次、不启动第二次运行；保留原有用户授权。
- 真正执行中断会保存已完成项并清理本批新增权限。恢复只核对已有点击回执/新标签；无法证明点击结果时停止，不重放点击。已保存岗位不重新打开、不重读正文。中断时未安全关闭的详情标签可保留。
- 新增独立“保存本批状态（诊断）”，导出 `career-queue-school-batch-diagnostic.json`，schema 为 `career-queue-school-batch-diagnostic-v1`；含阶段、已完成 ID、点击阶段、授权回执及清理事件，不含 JD、凭据或页面参数。
- “下载两岗岗位数据（导入用）”单击即下载，仍使用既有 capture schema；无成功项时禁用。旧单岗入口折叠并注明独立历史记录。

## 当前最少、安全的下一步

用户重新加载现有扩展至 **0.2.1** 后，打开扩展，**只点击“保存本批状态（诊断）”并提供该文件**。不点击准备前两岗、继续授权或运行；先用真实检查点判断先前有没有派发点击及完成项。升级保留原 IndexedDB 数据库名称，不清空旧单岗或两岗记录。

## 验证范围

专门回归覆盖准备期间重建、原生授权前后重建、不同弹窗、重复/拒绝回执、丢失开始回执、用户既有授权、点击前/后终止、成功保存后终止、完整捕获后清理，以及 0.2.0 截图对应的旧状态迁移。后台与弹窗使用实际模块和明确的 Chrome API 替身。

用户电脑独立 Edge 验证真实 DOM、新窗口、多文档跳转、原生 IndexedDB 和弹窗渲染；权限 API 使用替身，默认弹窗拦截负例也须通过。它不是用户 Brave 原生提示或学校真实批次验收。

完整回归/语法/whitespace/候选哈希结果保存在 `private/<local-evidence>`。项目无单独 lint/typecheck 脚本，不将未配置的检查称为通过。真实 Brave 两岗和实际权限撤销结果尚未验证；main 不提交、不推送。
