# 学校两岗小批 0.2.0

本轮只补齐已授权的学校岗位读取；不投递、不改学校提交历史、不自动导入。应用版本保持 2.10.2，扩展版本为 0.2.0。此前 0.1.9 单岗真实读取成功；本轮 Brave 原生授权和真实两岗验收仍待用户操作，不能称为整批已完成。

## 范围与操作

1. 在用户电脑的 Brave `brave://extensions` 中重新加载现有 Career Queue 扩展，确认版本 0.2.0。目录仍是项目的 `browser-extension`，不安装另一个副本。
2. 回到已登录的学校岗位列表 `/myAccount/coop/postings.htm`，打开扩展，点击“准备前两岗”。核对显示的两个学校 ID、标题。
3. 点击“授权并运行两岗”，本人确认 Brave 原生权限提示。请求仅为 `https://recruitstudents.torontomu.ca/*`；浏览器授权覆盖整个域名，实际代码只允许上述岗位路径。
4. 两岗完成后重新打开扩展，核对“已完成”“完成：2 / 2”和本批无持有权限。若原来已有学校域名或覆盖它的用户授权，界面显示保留原有权限；不会撤销用户原有授权。
5. 点击“准备下载已核对结果”并下载 JSON，在 `http://127.0.0.1:4322` 的学校捕获入口预览、核对后确认导入。导出成功不表示已投递。

只读当前列表前两个可唯一核对的岗位，单并发、岗位间至少两秒，不翻页。正常点击已观察到的职位标题，核对新标签 opener、创建前后标签集合、学校路径以及标题/公司/学期/可见 ID，再读取可见 JD、任期及申请说明。完整是指已识别的可见字段，不包括隐藏或折叠内容。对信息不足、登录挑战、403 类无法核对页面和异常路径停止。

仅关闭本批新建且再次核对身份成功的详情标签；原列表及其他标签保持。原列表被关闭时停止，详情标签保留。暂停在当前岗完成后生效；取消立即阻止后续步骤，未核对标签不关闭。

## 临时权限和恢复

准备阶段记录已有持久授权，实际请求由弹窗按钮的同步用户点击触发。新增权限在完成、暂停、失败或取消后撤销。后台重建读取 IndexedDB 检查点，只清理本批权限，不自动重放点击。权限不是浏览器原生的一次性授权：浏览器崩溃、关闭或本地存储损坏时可能残留，重新打开扩展会尝试清理。若显示 `PERMISSION_REVOKE_FAILED`，先点“重试撤销”；仍失败时本人在扩展详情中移除学校站点访问，再重新加载并核对。

浏览器拦截新窗口会得到 `NO_DETAIL_TAB_OBSERVED`，不会绕过设置或猜测详情 URL。拒绝授权不会打开职位。中断后通过“准备继续授权”及再次用户点击继续；若仍有原生权限提示，请先本人处理该提示。新批不会覆盖未完成的授权请求或待撤销权限。
