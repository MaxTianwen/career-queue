# v2 学校资料维护与关联纠正（2026-10-04，本机完成、未发布）

## 已确认规则与实现

锁定条件只看对应 School ID 是否存在学校渠道实际提交，不看官网提交。未学校提交可更新、解除、改绑；已学校提交可更新当前来源资料，但暂时不能解除或改绑。官网提交、所用材料和其他申请历史不会跟随关联迁移。学校提交后才发现关联错误的历史纠正功能留待单独设计。

- “学校对照 → 维护学校关联”提供来源字段更新、解除和改绑到本人已保存职位。粘贴发现来源变化时，可直接将非空新值带入维护草稿；缺失字段保留旧值，主动清空会出现在差异中。School ID 不可在资料更新中改写。
- 先预览变更，再填原因并确认保存；默认只突出变化，完整前后资料可展开。维护审计追加动作、前后关联 / 学校资料 / 职位快照、原因、操作者和时间。解除后仍可在“学校关联操作历史（含已解除）”查阅。
- 维护只修改学校关联表。原职位、JD、备注、材料、申请渠道和提交记录均保留原位；目标职位已有关联时拒绝覆盖。同一 School ID 不能通过重新导入绕过实际学校提交保护。
- 新增学校提交来源记录，按 School ID 与实际提交关联。记录时保存来源快照，后续更新不覆盖；后来确认的关联、旧库升级时已有关联和渠道更正分别标明记录依据，不能冒称来源在原提交日已知。界面与导出可查看来源和记录时间。
- 学校待办只把对应 School ID 的学校提交计入状态。旧提交保留其他 School ID 身份时，不将它当作当前 ID 已投；官网提交不触发维护锁定。
- 每次保存再次核对记录版本、当前提交状态和目标冲突；事务内写入关联及审计。重试不重复执行，解除后重导入也不接受旧版本重新修改。已处理请求的重试只确认原操作，不恢复已解除关联。
- 失败 / 刷新保留维护草稿及原版本；冲突需取消并重开核对。退出清空维护表单、预览和历史。
