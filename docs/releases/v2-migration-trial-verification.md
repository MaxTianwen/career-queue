# v2 隔离试迁（2026-10-05）

用户在只读预览完成后授权继续。本轮使用正式 v2 数据库的独立备份与恢复副本，仅在副本试迁；没有正式导入或推送。

## 实际结果

- 重新只读核对旧版存储，限定为已批准预览中的资料范围。若来源出现额外记录或提交，试迁停止，不默认扩大范围。
- 副本目标账号新增已选职位，标题、公司、地点、链接、JD、备注逐字段核对；原 v1 Key、时间、状态及其他字段保留在来源快照。
- 已生成的 DOCX / PDF 历史文件，校验原哈希、一页历史校验及来源计划；写入后和备份恢复后再次核对文件哈希。
- 文件仅作为历史原件保存，不启用为当前简历，不创建已审阅材料、v2 生成链、学校关联或提交记录。
- 试迁专用映射保存 v1 Key → v2 职位、版本 → 文件 ID、来源计划与原校验。该 `trial_migration` 表仅存在于隔离副本，不是已实现的生产迁移 schema。

## 通过的保护检查

1. 模拟职位写入后中断，事务回滚，职位和文件数恢复。
2. 相同快照重复执行不新增职位或文件；重新打开副本后重试仍返回原映射。
3. 来源指纹变化拒绝复用原迁移记录。
4. 试迁后完整备份并恢复至另一独立目录，映射及文件哈希一致。
5. 正式 v2 业务表前后指纹一致；未比较会话、临时 PDF 审阅、登录尝试和独立公共发现缓存，未写入这些表。

私人证据：`private/<local-evidence>` 指向独立目录中的 `verified.json`、`mapping.json` 和各备份。个人信息、文件、数据库及一次性试迁脚本不纳入 Git。无批量清理。

## 尚未完成

本轮只验证这一份真实样本，不代表学校已投、多学校 ID、同名冲突、缺失文件等复杂迁移已经支持。正式迁入功能仍需持久审计及可查看的旧版来源，尤其不能将历史生成稿自动视作当前基准对应的已审阅材料。
