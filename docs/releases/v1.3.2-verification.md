## 修复与回归

- 先新增受控慢操作测试，让定时 tick 在另一写操作持锁期间进入。修复前两个测试失败，分别抛出操作占用和模拟错误；记录保留在本机 `output/v132-busy-before.txt`。
- 修复后，只有定时 tick 收到 HTTP 409 且错误码为 `OPERATION_BUSY` 才返回明确的 deferred 结果。没有运行编号、没有搜索完成状态，不立即重试；下一次由原有日程再检查。测试确认持锁期间搜索次数与运行记录均为零，第二个写请求仍被拒绝，锁没有被失败请求提前释放；释放后仅搜索一次，当天再次 tick 跳过。
- 手动 discover、非忙碌 409、403、500 和其他真正错误仍抛错。检查总 POST 数，确认没有新增重试循环。
- 后台检查只输出网页服务 / 调度服务的已知状态、检查时间和有限原因代码。文件时间和每项服务时间分别检查，超过 90 秒、未来时间、缺失或损坏记录不作为当前健康依据；原始日志、命令和凭证字段不会被透传。实时日程认证成功与旧服务记录独立呈现。
- 视图测试覆盖记录过期时不显示当前已就绪、旧恢复建议不继续展示、失败后仍保留上次完成结果，以及启动 / 未配置时的建议。详情和运行历史的展开状态分别保存。
- 此次跨日测试发现旧刷新用例的模拟时钟与真实完成时间混用，导致误命中五分钟缓存。已让默认测试搜索时间来自同一模拟时钟；未修改产品缓存规则或用延长等待掩盖问题。
