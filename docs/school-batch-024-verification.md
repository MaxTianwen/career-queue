# 0.2.4：停止旧失败恢复死路

## 已证实的问题

0.2.3 的 failed/dispatched 恢复会保留旧 attempt，仅查找已有页面而不再次点击。原尝试没有页面时，再次“准备继续授权”不能产生新页面，会重复 NO_DETAIL_PAGE_CHANGE_OBSERVED。此前将此路径作为实机验证步骤不正确。

原权限短码搜索整个历史 events；旧 new-grant-revoked 也可能显示为当前撤权。没有浏览器授权提示并不等于权限拒绝；0.2.3 状态码不能确定实际 request 是否调用、是否已有覆盖授权，也不能确定提示是否显示。原始点击未产生页面的根因仍未知。

## 修复

- 旧失败未完成的 attempt 阻止直接 arm，禁用误导的继续和普通重新准备按钮；暂停、取消不能绕过核对。正常中断后的检查仍不重放点击，显示“仅检查旧尝试已有页面”。
- “保留失败证据并只读重新准备”只扫描原列表。它验证剩余原计划的 School ID、标题、公司、学期与唯一性，拒绝其它标签或变化的计划；不点击、不请求权限、不读取完整 JD、不关闭页面。
- 只读准备把原失败完整保存在本地 archives，保留计划、已采集岗位和 next；存储失败回滚内存。诊断导出保留失败元数据及完成 ID，不包含已采集 JD 正文。
- 只读准备后的 reviewed 状态不能直接运行；需独立点击“确认新尝试：之后将再次点击未完成职位”，然后另一个运行按钮才会请求所需权限。新尝试使用新批次、请求和 attempt ID，跳过已采集岗位。此能力不代表现在要求用户重试。
- 本轮 execution 区分 initial、inspect-existing、explicit-new。dispatchCall 只表示本轮调用打开函数，不证明网站点击成功或详情已打开；旧 step 不再被当作新点击证据。
- 每次权限请求使用独立 ID，记录 UI 实际 request 调用及 accepted/rejected/error；begin 记录不等于 request 已调用。提示是否显示始终 unknown。已有覆盖授权可无提示返回成功，不冒充拒绝。
- 撤权记录关联当前 request ID；状态和诊断只读查询当前 persistent/exact 权限。历史撤权不再冒充当前权限事实。权限请求异常与明确拒绝分开，原有用户授权仍保留。

## 当前操作边界

用户已要求不要重试，本轮仅修改和本地验证代码，没有操作真实 Brave 或学校页面。现在不要求授权、点击职位或运行两岗。未来若用户愿意，仅在重新加载 0.2.4 后、原学校列表当前激活时，可先点击“保留失败证据并只读重新准备”；该步骤测试确认不产生点击和权限请求。未明确同意新尝试前停在 reviewed。

没有修改 Shields、增加扩展权限、打开远程调试、改 既有申请历史、投递申请或提交/推送 main。

## 验证范围

新增旧失败形状、只读准备、归档回滚、原计划变化、重启、显式新尝试、保存进度、当前权限与旧撤权分离、无提示接受、request 异常、界面禁用及实际 popup 路由测试。完整测试与本机 Edge 合成页面证据见 private/<local-evidence>。合成浏览器使用用户电脑上的独立 Edge 测试配置，Chrome 权限 API 是明确模拟；不是 Brave 学校网站实测。未配置独立 lint/typecheck。
